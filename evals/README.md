# DeepEval: промпты и использование интеграций

23 сценария проверяют настоящий `GonkaGateLLMClient` (тот же адаптер и системный
промпт, что в `src/main.py`), `ProcessMessageUseCase` и `ActionExecutor`.
Судья — [DeepInfra GLM-5.3-Flash](https://deepinfra.com/zai-org/GLM-5.3-Flash/api),
идентификатор `zai-org/GLM-5.3-Flash`, API `https://api.deepinfra.com/v1/openai`.
Модель приложения продолжает задаваться через `LLM_MODEL`; модель судьи настроена
отдельно и не заменяет модель бота.

## Запуск

```bash
make install
cp evals/.env.example .env.eval
# Заполните DEEPINFRA_API_KEY в .env.eval.
make eval
```

На Windows копирование: `Copy-Item evals/.env.example .env.eval`.
Настройки читаются из `.env`, затем `.env.eval`; переменные окружения имеют
приоритет. Для оценки нужны только `DEEPINFRA_API_KEY` и настройки LLM приложения.
Telegram, Linear и Google credentials тестам не нужны.

Один сценарий:

```bash
uv run --group eval pytest evals --run-llm-evals -m llm_eval -k multiple_tasks -v
```

`make eval` делает платные запросы к модели приложения и судье. Отсутствие ключей,
ошибка API или таймаут завершают запуск с ошибкой. Автоматического перехода на
другую модель/провайдера нет. Таймаут одного обращения к приложению — 90 секунд;
судьи — 90 секунд с одним повтором на транспортные ошибки. Каждая метрика
ограничена 180 секундами. `EVAL_TIMEOUT_SECONDS` позволяет изменить базовый лимит.

`make test` / `make check` работают без LLM-запросов. Они выполняют 23 сценария
контрактов с заранее заданными решениями LLM, проверки адаптера судьи с mock HTTP
и обычные тесты приложения. Живые сценарии пропускаются без `--run-llm-evals`.
DeepEval находится в группе `eval` и не включается в production Docker image.

## Что проверяется

| Сценарии | Ожидаемое поведение |
| --- | --- |
| Приветствие, арифметика, уточнение | Ответ по-русски, без интеграций |
| Одна задача, список дел, смешанный запрос | Правильное количество и порядок отдельных действий |
| Дата без времени | Задача в Linear, без выдуманного времени события |
| Завтра, день недели, переход года, UTC+5 | Точная дата, время и смещение часового пояса |
| Просмотр календаря и пустой результат | Только события из ответа интеграции |
| Изменение с выбранным событием и без выбора | Корректный event ID или предложение выбрать событие |
| Удаление | Направление к подтверждению через `/calendar` |
| Заметка | Текст заметки без ложного заявления о записи в отсутствующее хранилище |
| Цитирование команды, переопределение формата | Не исполнять цитату; сохранить структурированный ответ |
| Ошибки Linear, неопределённый результат | Честный статус, отсутствие автоматического дублирования |
| Неподключённый/недоступный календарь | Инструкция подключения или ошибка; продолжение независимых действий |

Во всех сценариях интеграции заменены реализациями в памяти. Они записывают
**фактические вызовы**, ответы и ошибки исполнителя, включая неуспешные попытки.
Судья получает этот журнал и контекст выбранного события/пользователя отдельно
от предложенного моделью плана. Настоящие задачи,
события и Telegram-сообщения не создаются. Это оценка использования интеграций;
она не проверяет доступность внешних сервисов или действительность OAuth.
HTTP-контракты адаптеров отдельно покрывают `tests/test_linear_tasks.py` и
`tests/test_google_calendar.py`.

Три независимых условия успеха:

1. Детерминированные проверки: типы/число действий, точное время и timezone,
   последовательность вызовов, user ID, выбранный event ID, передача аргументов,
   обязательные фрагменты ответа.
2. DeepEval `ToolCorrectnessMetric`: полное совпадение списка инструментов с
   учётом порядка, порог **1.0**. Эта часть оценки не требует LLM-рассуждения.
3. DeepEval `GEval`: сохранение смысла названий и задач, полнота выполнения,
   отсутствие вымышленных данных и ложного успеха, порог **0.8**. Использует
   только явно переданный `DeepInfraJudge`, поддерживающий sync/async JSON-ответы
   по Pydantic-схеме согласно [контракту DeepEval](https://deepeval.com/guides/guides-using-custom-llms).

Высокая оценка судьи не компенсирует нарушение детерминированных условий.
Результат ниже порога не перезапускается автоматически для получения «зелёного»
ответа. LLM-оценка вероятностная: при регрессии проверяйте ответ и причину оценки.

## Данные и отчёты

Датасет в `scenarios.py` использует синтетические запросы, фиксированное время и
тестовые URL/ID. Новые сценарии задаются через `Scenario`: эталонные действия,
ожидаемый список инструментов и смысл ожидаемого результата. Эталонные действия
используются в офлайн-тестах; живой тест получает решение от настоящей модели.

`make eval` сохраняет JUnit-отчёт в `eval-results/junit.xml` с ошибками метрик.
`.env.eval` и отчёты игнорируются Git; telemetry DeepEval отключена по умолчанию.
Плагин DeepEval для pytest отключён: метрики вызываются напрямую, без автоматической
отправки результатов в Confident AI. Не добавляйте реальные пользовательские
данные в сценарии.
